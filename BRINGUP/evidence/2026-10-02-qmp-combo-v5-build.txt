Remaining risk / next step
- Code inspection shows the Glymur LN0/LN1 drive-level table is programmed in `qmp_v8_configure_dp_clocks()`. Later `set_voltages` updates go through `qmp_v4_configure_dp_tx()`, which does not refresh those LN0/LN1 registers. This is a separate possible link-training limitation; the candidate may clear the clock-enable failure yet still fail training. An upstream review also flagged this distinction; the candidate does not claim proven video output.
- Stage safely with `sudo bash ~/a16.sh qmpdp`. This does not live-unload/load the PHY module; it backs up any existing override and updates the initramfs only if that initramfs contains the module. After the script confirms `STAGED`, reboot, start `sudo bash ~/a16.sh display watch`, and connect the USB-C monitor once. A reboot/reset remains possible. Revert with `sudo bash ~/a16.sh qmpdp revert`.
