5120x1440 / 3840x1080 are the MSI's modes, so the MSI - the monitor whose DP
repeater fails channel equalization on every USB-C attempt - came up on the A16's
**HDMI** output, simultaneously with the internal panel, with:

    DP training failures this boot        0
    DP "prepare failed"                   0
    DPU "vblank timeout"                  0
    DPU "wait for commit done returned"   0

The HDMI path does not go through the monitor's internal DP repeater: the A16's
HDMI output is a display pipeline on the tertiary combo PHY (`phy@88e1000`, whose
`com_aux` clock-domain fix from 2026-09-17 is in force - this boot logs no
`com_aux`/`phy init failed` lines), so the failure mode that takes out USB-C DP
on this monitor is simply not in the path.

Note: at the time of this check the HDMI connector had gone back to
`disconnected` (with `enabled` still set), so the monitor had been unplugged or
the link dropped - the connect/enable above is recorded from the watcher's
snapshot, not from the current instant. The user should confirm whether the
picture was visible and stable.

## USB-C DP, for comparison

and #2 plus the sink segment all succeed) with the cap in force. Every failure in
